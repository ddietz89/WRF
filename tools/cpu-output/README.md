# Opt-in root-thread WRF output compression

Opt-in working tool qualified on the experimental GNU WRF configuration. There are no binaries, automatic builds, production installs, default changes or WRF source modifications here. All four C/header files are byte-for-byte copies of tested sources. The final shim supports only configured MPI worlds 16/64 (unset 16); invalid configuration declines activation. Byte-provider arithmetic, framing and callback code are unchanged from qualification.

## Dependency and build

This is not usable with ordinary stock NetCDF alone. The existing NetCDF-C 4.9.2 owner extension exports `nc_precompressed_provider_begin/end` ABI v1; installed read-only owner SHA 8adc33059a98399cd8adea41de071598aaa2b09ff53eb3ae860cad0c6696b538 is `/pool/wrf/WPS_new/runtime/netcdf-owner/lib/libnetcdf.so.19`. `owner-provenance.json` pins the original patch, packaged build receipt and owner error/oracle evidence; the source/build mechanism is retained at `investigation/backend-integration/netcdf-owner/`. The deployed SHA equals the packaged build output SHA in that receipt, as separately verified by the installed-owner closure and WPS installation inventory. The earlier experimental 4653 library is not the deployed 8adc artifact. This package builds only the shim; it does not rebuild NetCDF/HDF5 or copy installed dependencies.

Build into a fresh experimental directory: `python3 build.py --output-dir /pool/wrf-experiment/wrf-cpu/builds/cpu-output-FRESH`. The script checks source/dependency hashes, rejects an existing output directory, removes launcher preload, uses the same GNU 13.3 MPI compile flags as qualification, compares the packaged ABI header to the pinned installed owner header, and records compiler/symbol/dynamic build closure and the selected nonsecret toolchain environment. The shim resolves NC entrypoints dynamically inside the actual model: build-time `ldd` does not prove its model NC/Fortran/HDF closure; the frozen launcher and actual loaded-map checks do. No sudo or install operation occurs. The packaged reproducibility build produced SHA256 `1476aeed371784a03b37e9d4bb5b1aeb5007d9989ca9ad90771c5a9f7e3e3f79`, exactly matching the full-grid model-tested binary. Different binaries or dependency closures require qualification. This tool intentionally accepts only the qualified stack; AOCC/Intel are not qualified by this result.

Qualified dependency scope is GNU 13.3, OpenMPI 4.1.6 UCX/XPMEM, NetCDF-C 4.9.2 owner, Fortran 4.6 ABI and HDF5 1.14.3 with the pinned stock zlib ABI or qualified job-local zlib-ng compatibility library. MPI/lib must precede GNU deps/lib because the latter contains an older MPI. Runtime C/Fortran NC, HDF, MPI/Fortran-MPI and codec mappings must be checked against the frozen campaign closure, rather than inferred from environment variables.

## Launch contract

Apply preload only to actual WRF ranks via mpirun `-x LD_PRELOAD=ABSOLUTE_SHIM` (stock) or `-x LD_PRELOAD=ABSOLUTE_SHIM:QUALIFIED_ZLIB_NG` (NG). Keep `LD_PRELOAD` absent from mpirun, Python, ssh, taskset and helper environments: the constructor requires the actual MPI/NC symbols. Set the owner search path before stock NC, with qualified MPI/lib before deps/lib. Use the qualified `mpi-ib-env.sh` (`rc,sm,self`, `ibp1s0f0:1`) for IB/shared-memory data transport.

The frozen launcher sets numeric `OMPI_MPI_THREAD_LEVEL=1`; the shim additionally proves MPI initialized, not finalized, main thread, actual supplied FUNNELED-or-better, and actual global rank 0/world equality. No MPI calls occur in byte workers. Enabling environment values alone do not authorize or prove resource placement.

Required settings: `WRF_ROOT_SHIM_OPTIN=1`, `WRF_ROOT_SHIM_OPTOUT=0`, `WRF_ROOT_SHIM_WORLD=16|64`, `WRF_ROOT_SHIM_OWNER=canonical 8adc path`, `WRF_ROOT_SHIM_ROOTCPU=actual root singleton`, `WRF_ROOT_SHIM_CPUS=sorted exact root 19 effective cpuset`, and `WRF_ROOT_SHIM_LOGDIR=new owned rank-log directory`. Root MPI placement remains the 16 singleton rank cores; root cgroup grants those 16 plus dedicated worker cores 24,25,26, quota 1900%. Worker 0 shares the root singleton; other three use 24,25,26. The main affinity widens only during the pure byte callback and is checked restored before any owner HDF/MPI call on every status path. Other ranks return before root-only resource activation; remote nodes require only 16 rank cores/quota 1600%.

Only eligible little-endian F32 complete spatial requests of one Time plane are supplied: existing chunk order/geometry/fill, shuffle 4, zlib-wrapped deflate level 2, and output layout remain unchanged. HDF/NetCDF stay on the owner main thread. Unsupported requests use the ordinary owner path. Partial chunk-commit failures never retry ordinary writing. Begin/end, release ownership, status, errno, fenv and affinity have bounded public-ABI tests.

## Qualification evidence

World 16 common March corrected-stock one-hour: both hourly outputs passed unchanged exact field/mask/nonfinite/metadata/type/layout checks, and all 185 ordered adaptive steps matched the retained control prefix. Root 432 callbacks/supplies/releases and widens/restores balanced, zero pending/errors/foreign events; fifteen nonroots inactive. Development output times 4.679/5.261s versus same-node prior instrumented stock 6.856/7.497s, with different load and three extra cores: no matched stage/model gain claim.

The final world 64 variant passed the full-grid 1500×1140, 8×8 decomposition, 15-minute combined-source/zlib-ng run: both complete histories passed the original exact scientific, metadata and layout checker, and all 50 ordered logged adaptive steps matched the retained control. All 64 actual rank/library closures and InfiniBand transport records passed; root 432 callbacks, supplies, releases, affinity widens and restores balanced, with zero pending/error/foreign events. All 63 nonroots remained inactive. Initial/hourly output writes were 61.779/68.022 seconds versus retained combined-source/zlib-ng 74.161/86.421 seconds. These are development measurements with shared load and 67 allocated physical cores versus 64; they establish no matched stage or pipeline speedup. The world-16 model evidence above used the preceding world-16 shim; the final variant extends its guarded world selection to 16/64 without changing provider byte arithmetic. Qualification is specific to the tested pure-MPI callers and layouts; arbitrary decompositions, OpenMP WRF, restart equivalence and other compilers remain unqualified.

Rollback: omit the rank-only shim preload or set `WRF_ROOT_SHIM_OPTOUT=1`; retain the qualified ordinary NC dependency closure. No system loader configuration or existing production files change. Never enable this package through global `LD_PRELOAD` or silently make it the default.

## Fail-closed limits

Use a fresh empty log directory. Every expected rank constructor and final record is mandatory in the external checker; failed exclusive log creation may leave no record, and does not provide qualified silent success. Unset WORLD intentionally describes only a16-rank job; a64-rank launcher must explicitly set64 and require64 completed logs. OPTOUT=1 suppresses OPTIN=1; without opt-in the feature is already disabled.

The launcher, not the shim, proves all rank/core roles and lease authorization. Frozen common16 root rank cores are sorted(16*n+4/5) for n0..7, root singleton4; full64 root node rank cores are sorted(16*n+0/1), root singleton0. Each root containment set adds exactly24,25,26; each remaining node uses its16 singleton rank list. The shim checks actual singleton and exact effective cgroup equality to the declared root19 set, but environment values alone cannot establish those role assignments.

A supplied provider result must be released exactly once before the outer put returns. Missing/duplicate release, pending buffers, or failed singleton restore intentionally abort before unsafe owner HDF/MPI continuation; these are contract failures, not ordinary-path retries or opt-out rollback. Partial chunk commit has no fallback. Rollback selects ordinary writing before a new run, and does not undo already committed chunks.
