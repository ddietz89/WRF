# RTRNMC automatic-storage placement screen

Closed unpromoted. Strict native checks passed and the 11 malloc/free sites each became zero, but the complete-caller result did not show a significant consistent gain.

The candidate compiled the exact current complete RTRNMC procedure with GNU13.3 strict O2 and only `-fstack-arrays` added. It retained the original 36 finite and six safe-source IEEE cases, full physical outputs, padding, read-only inputs, all five compute-state words and genuine O2 raw gold. The standalone public module bytes matched. This qualified the extracted procedure; no whole-LW module or forecast was built.

The cost fixture was the original **synthetic** 33-layer,140-gpoint mixed-mask4 complete caller,20,000 calls per arm. All eight full output restores and the entire call were timed. State resets, state reads and checks were outside each measured interval. Each arm used CPU24,4GiB,zero swap and a checked cache clear; all four raw/state and normal-closure checks passed.

The first round ran 01 parent +02 candidate; the second ran 01 candidate +02 parent. On hpc01, candidate wall/thread CPU were **1.4487%/1.4573% lower**. On hpc02 they were **0.1720%/0.1664% higher**. These are one opposite-order pair per host, without a stable gain or forecast occupancy claim.

At33 layers,38,164 logical scratch bytes moved from heap to stack; the same elements remain allocated, with stack alignment/frame overhead additional. No peak-memory or capacity benefit was measured. Changed target instructions, register scheduling and target unwind metadata remain explicit in the private machine record; the finite native result is not a universal NaN,trap or whole-module equivalence claim.

No source/default/image selection was changed. No further timing matrix, whole-LW build or application test is planned for this fixed candidate.
