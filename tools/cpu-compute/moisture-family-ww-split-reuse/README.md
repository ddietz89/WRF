# Moisture-family WW preparation reuse

The first admitted moisture species prepares WW scratch over every tile. Later species reuse that scratch within the same RK stage. Readiness resets before each moisture loop and is set only after the first complete tile pass. Implicit advection and absent/false flags retain the original work; unsupported builds retain the original interface.

The complete six-species synthetic routine-family caller was 3.4199% and 3.4279% shorter in opposite-order node pairs, with exact raw/state/guard checks. Process CPU fell 3.4401% and 3.8453%. This is a caller measurement, not a forecast percentage. Scalar updates and halo exchange are outside that interval.

The combined89bd image retains all prior selected components/providers and passed its own two-output/35-step and four-output/545-step three-hour full512 checks against corrected-original546b, including exact science, metadata/layout, placement and output ownership. Nine-hour, profile, restart and full144-hour coverage remain unqualified. The three-hour observation used a retained control, without a new matched forecast timing pair. The qualified default is `WRF_MOISTURE_WW_SPLIT_REUSE=1` under the stated GNU13.3 pure-MPI guards. Set it to0 and fully regenerate, rebuild both modules and every caller, rearchive and relink to opt out. Adding the optional argument changes the Fortran ABI; retaining old compiled callers is invalid. Production and master remain unchanged.
