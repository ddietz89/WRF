# INATM copy grouping

The five-way split is rejected. It passed the original full-module O0/O2 correctness checks but made the fixed complete-INATM caller 6.8912% slower on hpc01 and 9.6713% slower on hpc04. Its evidence remains in the `FIVE_WAY_*` files. Removing stack loads alone did not demonstrate a gain.

The single 2+3 repair is retained pending application qualification. It groups the first two copy families and the remaining three inside the unchanged layer loop, leaving the three radius copies once per layer after both groups. The candidate starts from the original selected a21/513 parent, not the rejected five-way source. Actual assembly has two scalar copy-loop backedges and no stack access inside either loop, versus six per-element stride reloads and a stack counter in the original loop. It does not reduce copied bytes or allocations and does not vectorize the copies.

The complete-INATM caller was 20.0306% shorter on hpc01 and 17.7202% shorter on hpc04 in opposite orders. Each arm used five separate 20,000-call processes, for 100,000 complete calls in one fixed 140-point, 33-layer synthetic geometry. Only the existing CLOCK_MONOTONIC_RAW intervals around `invoke()` were summed; these include the descriptor wrapper and actual INATM. Restoration, reset, five-state observations, raw comparisons and read-only checks were outside those clocks. Whole-process CPU is context only. Every batch matched the original 104,444-byte raw/state result; caches, zero throttling, memory events and strong closures passed.

The original 16-case O0/O2 descriptor, tail, raw, read-only and IEEE checks passed. The existing 34-module contract retained 33 exact module files and the narrowly proved imported-ID swap in one file; no interface was normalized. This is a measured complete synthetic caller result, not an isolated copy-kernel, whole-LW, forecast or global-headroom claim. Canonical source, selected executables and defaults are unchanged pending the original application checker. No further grouping variants are proposed.
